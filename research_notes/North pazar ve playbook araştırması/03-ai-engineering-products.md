Date: 2026-10-16. Scope: the product/workflow layer only (intake → plan → build → verify → preview → deploy → iterate → rollback → cost). Skills, sandboxing, stack and deterministic gates are covered in `docs/research/dept-engineering.md` and are not repeated. ## KQ1. Product teardown: what each product does, how a request becomes an outcome, pricing, verification

### Takeaway
By October 2026 every serious builder converges on the same spine: a read-only **Plan mode** that asks questions and produces an approvable plan, an autonomous **Build mode** that bills by effort, a **live preview with element-pinned comments**, automatic **per-message versions with one-click revert**, a **browser-driven self-test** the agent chooses to run, a **security scan on publish**, and a **built-in backend + payments** so the user never creates a Supabase or Stripe account. The cloud coding agents (Devin, Cursor, Codex, Claude Code, Copilot, Jules, Factory) converge on a different spine: isolated VM, plan approval, diff view with inline comments, PR as the deliverable, artifacts (screenshots/video) as proof, and event-driven auto-fix of CI and review comments.

## KQ5. State of the art in agentic coding harnesses (OSS repos, papers, Anthropic guidance) worth borrowing as workflow patterns

### Takeaway
The transferable patterns are: a read-only plan/architect phase (Cline, Aider, Roo), subtasks with isolated context that return only a summary (Roo Orchestrator; Lovable/Devin subagents), guardrails that reject bad edits before they land (SWE-agent linter), small bounded views instead of whole files, collapsed history, and an evaluator separate from the generator (Anthropic). Anthropic's own advice is to start with workflows, add agency only when measured, and design tools with poka-yoke.

### Cited Findings
- SWE-agent ACI ablations (GPT-4 Turbo, SWE-bench Lite): full config 18.0% vs 11.0% shell-only ("a 64% relative increase"); no linter guardrail 15.0% (↓3.0) — "Invalid edits are discarded, and the agent is asked to try editing the file again"; file viewer 100 lines 18.0% vs 30 lines 14.3% vs full file 12.7%; summarized search (≤50 results) 18.0% vs iterative search 12.0%; collapsing older observations (keep last 5) 18.0% vs full history 15.0%; "51.7% of SWE-agent trajectories contain one or more failed edits"; success after one failed edit drops to 57.2% — [arxiv html](https://arxiv.org/html/2405.15793v3), [abstract](https://arxiv.org/abs/2405.15793).
- OpenHands: "safe interaction with sandboxed environments for code execution", multi-agent coordination, evaluation on 15 benchmarks incl. SWE-bench and WebArena, MIT — [arxiv](https://arxiv.org/abs/2407.16741).
- Cline Plan/Act: Plan "cannot modify files or execute commands"; "The conversation history carries over when you switch modes"; different models per mode; "Enable Checkpoints before Act mode so you can roll back" — [cline docs](https://docs.cline.bot/features/plan-and-act).
- Roo Orchestrator: "Each subtask operates in complete isolation with its own conversation history"; "only this summary returns to the parent"; "By default, you must approve the creation and completion of each subtask"; orchestrator cannot read/write files by default — [roo docs](https://roocodeinc.github.io/Roo-Code/features/boomerang-tasks).
- Aider architect mode: main model proposes, `--editor-model` "converts that proposal into specific file edits"; "Certain LLMs aren't able to propose coding solutions and specify detailed file edits all in one go"; costs two requests — [aider](https://aider.chat/docs/usage/modes.html).
- Anthropic "Building effective agents": "The most successful implementations use simple, composable patterns rather than complex frameworks"; patterns prompt-chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer; agents "pause for human input at checkpoints or when blocked"; stopping conditions such as max iterations; poka-yoke tool design ("requiring absolute file paths"); "consider adding complexity only when it demonstrably improves outcomes" — [anthropic](https://www.anthropic.com/research/building-effective-agents).
- Anthropic long-running harness posts (planner + builder + skeptical Playwright evaluator; `feature_list.json`; "every harness component encodes an assumption about what the model can't do alone"; $124.70–$200 per full app) — already summarised in `docs/research/dept-engineering.md` §5 from [Nov 2025](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) and [Mar 2026](https://www.anthropic.com/engineering/harness-design-long-running-apps).
- Claude Code cloud: auto-compaction triggered partway through the window; subagents "offload research or parallel work into a separate context window"; agent teams behind `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` — [docs](https://code.claude.com/docs/en/claude-code-on-the-web).
- Managed Agents: "built-in prompt caching, compaction"; steer or interrupt mid-execution; scheduled deployments — [overview](https://platform.claude.com/docs/en/managed-agents/overview).
- Factory: Missions want "Agent Readiness Level 4 (Optimized)" repos; harness customisation via AGENTS.md, skills, hooks, subagents — [docs](https://docs.factory.com/), [missions](https://docs.factory.com/docs/missions/overview).
- Jules AGENTS.md: "Jules now automatically looks for a file named AGENTS.md in the root of your repository" — [docs](https://jules.google/docs). Devin AGENTS.md and "Memory and Dreaming" pages exist — [docs index](https://docs.devin.ai/llms.txt).

### Inferences
- North's harness should encode SWE-agent's three cheap wins directly in tools: reject edits that fail `tsc`/ESLint on the touched file (not just at the end), expose bounded file windows and capped search, and collapse old tool output (the SDK's compaction covers the third).
- Roo's "summary-only return" and Lovable's read-only subagents are the same idea as North's fresh-context evaluator; extend it to the planner's research subagents so plan cost stays bounded.
- Aider's architect/editor split is the cheapest way to use Opus for planning and Sonnet for edits, which matches the persona budgets in dept-engineering.

## KQ6. What North should adopt (ranked) and what to avoid

### Takeaway
North should copy the consumer builders' review surface (pinned comments on a live preview, per-message revert, cost check-ins) and the engineer tools' proof surface (diff + artifacts + auto-fix), while keeping what no one else has: worker-side re-verification and the K2 go-live card.

### Cited Findings
- Evidence for each ranked item is in KQ1–KQ5 above; the items below reference the product that proved the pattern.

### Inferences — ranked "features North should adopt"
1. **Plan card = editable, versioned plan with compact clarifying questions and timeout auto-approve.** Lovable plan versions/section comments, Base44 "one or two compact cards", Jules timer auto-approve. Store the approved plan in the repo as `feature_list.json` + `PLAN.md` (Lovable `.lovable/plan/`). Fits DEC quota: one card per build.
2. **Cost check-ins on the live work view.** Show time + credits so far (Lovable Aug 25 2026), pause at a threshold with Continue / Wrap up (Lovable 20-credit default), confirm before any paid escalation (Replit). Surface the `maxBudgetUsd` cap as a visible meter, not a silent kill.
3. **Preview toolbar for the CEO: select element → describe, pin comments, draw annotations; "send thread to Engineering" creates a fix task.** Lovable (S/T/C/D keys, free comments), Base44 pinned comments, v0 screenshot-of-element attached to the instruction. This is how a non-technical founder iterates without the chat box.
4. **Version per task with one-click revert, plus explicit data vs code rollback.** Lovable history/bookmarks (code only, no credit refund), Base44 per-message Revert + checkpoint before auto-fixes, Replit DB rollback. North: revert = new commit on `build/<id>` + redeploy preview; database restore is a separate K2 card.
5. **Artifacts as proof on the decision card.** Cursor attaches screenshots/video/logs to the PR; Devin recordings as pass/fail cards; Replit replayable test video. North's go-live card should embed gate scores (Lighthouse/axe), the Playwright recording and the synthetic-signup row.
6. **Follow-ups while working, applied at the next stopping point.** Lovable Sep 8 2026, Codex queued messages, Copilot steering (each = 1 premium request). Cheap to add to the live work view; prevents stop-and-restart waste.
7. **Drafts/variants without touching main and without extra quota.** Lovable Drafts (free to create/accept), Replit Design Canvas "Explore", Base44 Compare models (2× credits). North already plans `variant/a|b|c` branches; present them in the review queue, not as cards.
8. **Built-in-first integrations with approval only for migrations and access widening.** Lovable Cloud/payments, Base44 auto-approve rule, v0 Marketplace provisioning. North: "managed by North" waitlist + Resend by default; migrations and RLS changes are K1; moving to the founder's own Supabase/Stripe is K2.
9. **Secure-input step for secrets; agent never sees values; chat detects pasted keys.** Lovable Connect Stripe form + chat key detection; Claude Code/Cursor broker secrets outside the VM.
10. **Auto-fix PRs from CI failures and review comments, asking on ambiguous or architectural ones.** Claude Code Auto-fix, Cursor CI wake-ups, Jules CI Fixer. Map "asks you" to a K1 note, never a card.
11. **Security scan at publish with block-on-critical, shown as grouped findings with one-click fix.** Lovable Quick/Deep scan (block default only for Enterprise), Base44 fixes with checkpoint. North: make block-on-critical the default; findings appear on the K2 card.
12. **Edit guardrails from SWE-agent inside the generator's tools** (reject edits that break typecheck/lint on touched files; bounded file windows; capped search).
13. **Read-only research subagents with summary-only return** (Lovable subagents, Roo Orchestrator) for the planner and reviewer, with their own budget.
14. **Task board for background work: Drafts/Active/Ready/Done, "apply" as explicit step** (Replit) — maps to North's review queue states.
15. **Session logs linked from every commit** (Copilot) — `agent_runs` id in commit trailers so `actions`/`ledger_entries` tie to code.

### Inferences — patterns to avoid
- **Opaque per-message or token billing with no in-flight visibility** (Bolt tokens driven by file sync; Emergent credits undefined on the pricing page). It is the dominant complaint across Trustpilot and review sites.
- **Agent-side verification only.** Lovable's "Most verification tools run only when you ask for them", Copilot's "Logs do not replace your own review and testing". Never mark a North task done on the agent's `test_report`.
- **Whole-file rewrites on fix tasks** ("every fix breaks something else"). Require diff-scoped edits + visual baseline gate for fix tasks.
- **Mixing a test step into a large build prompt.** Lovable warns stopped browser tests can lose that step's work; North runs gates as a separate Inngest step after commit.
- **Letting drafts/variants share the production database** (Lovable Drafts caveat). Variants in North must point at the sandbox-mode backend.
- **Design-direction questionnaires before the first build.** Lovable removed them Oct 8 2026; Base44 skips the mockup question for web apps. Ask once about brand inputs, then build.
- **One-way migration traps** (Lovable Cloud ↔ Supabase, Bolt Database → Supabase "no supported way"). Keep North's generated schema portable (plain SQL migrations in the repo).
- **Unbounded session length as a feature** (Lovable 10-hour messages, `/goal`). Without check-ins this is where runaway cost lives; pair any long-run mode with the cost meter and per-persona caps.
- **Draft PR replies and comment-triggered automation surprises.** Claude Code warns Auto-fix replies on your behalf can trigger Atlantis/Terraform-style workflows; North's PR comments must be posted as the North app, gated by `AuthorityEngine.gate()`.
