# Rebuttal: implementing engineer

**Q1 Stop control: CONCEDE.** One tap is what `KillSwitch` already does (kill-switch.tsx:182-198) and what e2e asserts with `click()` (m0:37, flows.ts:72); it keeps the ≤ 100 ms optimistic `data-stopped` on `<html>` trivial and needs no pointer-cancel code on iOS. Hold-to-confirm stays only on money/send options. Edit 04 "The stop control" as the advocate wrote it.

**Q2 Type: CONCEDE, verified.** `next/font/google`'s font data (next 16.4.1) lists Source Serif 4 with axes `opsz` 8-60 and `wght` 200-900, so `Source_Serif_4({ axes: ["opsz"], subsets: ["latin"] })` is valid. The served Latin woff2 (122 KB, variable) carries GSUB `tnum`, `pnum`, `liga`, `frac`; `lnum`/`onum` are absent because its default figures are already lining, so `font-variant-numeric: tabular-nums` yields tabular lining figures. Two files (roman + italic) meet 02's budget. If `tnum` were ever stripped, the fallback is `next/font/local` with the upstream OTF; not needed. Mono: IBM Plex Mono 400 only (static weights on Google Fonts), used solely in `.prose-north code/pre` and ids.

**Q3 Signature: CONCEDE; the merge is cheaper than the draft.** Collapse-in-place removes the shared-element problem entirely: no `experimental.viewTransition`, no Motion, no double flight after `revalidatePath(layout)` (actions.ts:79). Render one server list "Today's actions" keyed by card id (today's cards in creation order, each a card or a receipt row, plus K1 actions since the brief); the collapse is a height/opacity transition on the same keyed node, and the next card moves up for free. Non-negotiable inside it: commit immediately, worker `step.sleep` 5 s and honour `answer_withdrawn_at`; undo only on one-tap non-money cards; e2e keeps `data-answered` within 2 s.

**Q4 Accent: CONCEDE.** Red for stopped and failed only; ink fill marks "Recommended"; `aria-pressed` and the check appear only on selection; nothing autofocused (tab order still reaches it). The greyscale gate (07:71) then tests fill, which is what it can see. Today's idle `border-error text-error` on the stop button (kill-switch.tsx:196) goes.

**The one thing I still fight: timed keyboard holds.** "Enter held 600 ms" (advocate Q2, 04:169) is not implementable reliably: `keydown` auto-repeats at OS intervals, switch access and voice control cannot hold a key, and Playwright can only approximate it. Keyboard money confirmation must be a second deliberate press: 1/2/3 selects and relabels the option "Confirm: spend $40"; Enter commits; Esc cancels. Pointer users hold; keyboard users press twice. Same safety, zero timing dependence.
