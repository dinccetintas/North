# M5 — Proactive layer

Goal: the user runs the company for 7 days answering only cards: morning brief,
signals, error-to-fix loop, weekly plan revision.

Requirements: BRF-1, PRO-1, PRO-2, PLN-2.

## Deliverables

- `daily-brief` cron per user timezone; brief = yesterday, metrics, pending
  cards, today's plan; push + email; readable in 60 s (word budget enforced).
- Signal scanner: Reddit (read-only), Product Hunt, Google Trends, competitor
  sites; Haiku scoring; threshold → card with evidence links; weekly cap on
  "new opportunity" cards (PRO-3 is V2 but the cap exists now).
- Sentry webhook → operations role → engineering fix task → PR → preview
  evidence → go-live card (PRO-2).
- `plan-week` revision uses `OutcomeLedger.channelReport`; shrinking task types
  carry a written rationale (PLN-2).
- Observability: Langfuse traces, Sentry for the app, cost dashboard in settings.

## Acceptance test

Simulated 7-day run (clock-advanced in the smoke harness) with `MockRuntime`:
7 briefs, ≥2 signals → ≤2 cards, 1 error → fix task → card, week-2 plan
differs from week-1 with rationale text; the user "answered cards only" (no chat
events). Latency: brief generation under 60 s per company.
