# M1 — Core loop (K0 only)

Goal: from an idea text, within 24 hours the company has a market report,
personas, a competitor map, a PRD, a business plan and an investor deck draft as
versioned artifacts, plus a weekly plan from the Chief of Staff. No external
action yet (every task in M1 is K0).

Requirements: ONB-1, ONB-2, PLN-1, MEM-1, MEM-2, AGT-1 (statuses), CHAT-1 (basic).

## Shared contracts (written first, in `packages/core`)

- `tasks/types.ts`: `TASK_TYPES`, `TASK_OWNER`, `METRIC_KEYS`, `AgentOutputSchema`
  (summary, artifacts[], memory[], actions[], confidence), `PlanOutputSchema`
  (summary, rationale, tasks[] with taskType/metricKey/expectedDelta/cost),
  `outputJsonSchema(taskType)`.
- `onboarding.ts`: `ClarifyingQuestionsSchema` (≤5), `ClarificationAnswersSchema`,
  `GoalInputSchema`, `BudgetInputSchema`, `ONBOARDING_STEPS`, `fallbackQuestions()`.
- `events.ts`: `task/finished` payload (`TaskFinishedSchema`).

## Work packages (parallel; disjoint files)

### WP-A backend data (persona: north-backend) — `packages/db`

Migration `0002_m1.sql`: `companies.onboarding_step text default 'questions'`,
`theses.clarifications jsonb default '[]'`, `memory_items.search tsvector`
generated column + GIN index, SQL function `search_memory(p_company_id uuid,
p_query text, p_limit int)` (ranked FTS over title+content), Storage bucket
`artifacts` (private) with owner-scoped policies, `tasks.task_type text not null
default 'market_report'`, `tasks.output_summary text`, `plans.status`.

Repositories (each file < 300 lines, typed with generated `types.ts`):
`theses.ts` (currentThesis, saveClarifications, addThesisVersion),
`goals.ts` (createGoal, listGoals), `budgets.ts` (upsertBudgets, listBudgets),
`onboarding.ts` (getStep, setStep), `agents.ts` (ensureAgentsForCompany from a
role list), `plans.ts` (createPlanWithTasks, latestPlan), `tasks.ts` (createTask,
getTask, listTasks, markRunning/markWaiting/markDone/markFailed via core
`transition`), `memory.ts` (writeMemoryItems, searchMemory via rpc,
memoryDigest(companyId, maxChars)), `artifacts.ts` (createArtifact uploads
markdown to Storage at `companies/<id>/<kind>/<slug>-v<n>.md`, listArtifacts,
getArtifactMarkdown, nextVersion), `ledger.ts` (recordLedgerEntry),
`actions.ts` (recordAction), `agentRuns.ts` (recordAgentRun), `metrics.ts`
(latestMetric, recordMetric). Integration tests for each against the local stack.

### WP-B agent runtime (persona: north-agent-runtime) — `packages/agents`

- `llm/client.ts`: `LlmClient` interface `{ structured<T>(schema, system, user) }`,
  `AnthropicLlm` (uses `@anthropic-ai/sdk` with `output_config.format` JSON
  schema, model from `resolveModel`), `MockLlm` (deterministic).
- `onboarding/clarify.ts`: `generateClarifyingQuestions(thesis, llm)` returns
  `ClarifyingQuestions`, falls back to `fallbackQuestions`.
- `prompts/`: one builder per task type (`buildTaskPrompt(role, taskType, ctx)`),
  reading the role YAML `system_prompt` with `{{...}}` substitution.
- `runtime/claude-agent-sdk.ts`: `ClaudeAgentSdkRuntime` implementing
  `AgentRuntime` with `query()`: `cwd` = workspace, `settingSources: []`,
  `permissionMode: "dontAsk"`, `allowedTools` from role (WebSearch/WebFetch for
  research; `mcp__north__memory_search` for all), `mcpServers.north` via
  `createSdkMcpServer` + `tool()` (memory search backed by a callback),
  `outputFormat: { type: "json_schema", schema: outputJsonSchema(taskType) }`,
  `maxTurns`/`maxBudgetUsd` from role, `hooks.PreToolUse` audit callback, result
  → `AgentRunResult` with `structured_output`, `total_cost_usd`, `modelUsage`.
- `runtime/select.ts`: `selectRuntime(env)` → mock or sdk.
- `fixtures/`: Mock scripts for market_report, personas, competitor_map, prd,
  business_plan, investor_deck, plan_week producing realistic markdown.
- Unit tests for prompts, clarify fallback, fixtures validity (every fixture
  parses with the output schema), and the SDK runtime option builder (pure).

### WP-C web (persona: north-frontend) — `apps/web`

- Onboarding wizard under `/c/[slug]/onboarding` with `?step=questions|goal|budget|summary`;
  server actions: `answerQuestions`, `saveGoal`, `saveBudget`, `approvePlan`
  (sets step `done`, sends `company/onboarded`). Questions come from
  `generateClarifyingQuestions` (sandbox: fallback). `/new` redirects to the
  wizard after creating the company.
- Company home: goal progress (latest metric vs target), weekly plan with task
  rows (status badge, role, title, cost), artifacts strip; auto-refresh every 5 s
  while any task is `queued`/`running` (client component calling
  `router.refresh()`).
- `/c/[slug]/artifacts` list + `/c/[slug]/artifacts/[id]` markdown view with
  download (`.md`).
- `/c/[slug]/team`: role cards (8 roles from `agents` table) + last 24h
  `actions` stream in terminal style.
- Playwright `m1-onboarding.spec.ts`: thesis → questions → goal → budget →
  summary → home shows plan tasks (with the worker running MockRuntime).

### WP-D worker (orchestrator) — `apps/worker`

- `onboard-company` (event `company/onboarded`): ensure agents; create and run,
  in order, research `market_report`, `personas`, `competitor_map`, then strategy
  `prd`, `business_plan`, `investor_deck` via `step.invoke(runTask)`; then send
  `plan/requested`.
- `plan-week` (event `plan/requested`): Chief of Staff `plan_week` run →
  `createPlanWithTasks` → fan-out `task/dispatch`.
- `run-task` (event `task/dispatch`): load task/company/thesis/memory digest;
  `markRunning`; runtime.run; persist artifacts + memory; gate each action (K0
  → record executed; anything else → record `blocked` in M1 with reason
  "not yet supported"); evidence = first artifact id (verified by lookup);
  `markDone`; `recordAgentRun`; ledger entry on `artifacts`; send `task/finished`.
  On failure: `markFailed`, retry once with a "different approach" note.
- `cancelOn: company/killswitch` for all three.

## Security review (north-security-reviewer, 2026-10-14) and fixes

Verdict before fixes: BLOCK (2 HIGH, 5 MEDIUM, 2 LOW). All HIGH and MEDIUM
items fixed in the same day; re-validated (74 integration tests, smoke M1, E2E).

| # | Finding | Fix |
| --- | --- | --- |
| H1 | Worker ignored the kill switch mid-run (`gate()` got `killSwitchActive: false`; `cancelOn` cannot abort an in-flight step) | `executeTask` returns `blocked` when `companies.kill_switch_active`; `gate()` reads the real flag; `plan-week` checks before planning; runtime deps gained `isKilled`, and the PreToolUse hook denies every tool call while the switch is on (one-turn latency) |
| H2 | Agent subprocess inherited the worker env (service-role key); engineering unlocks Bash | `buildQueryOptions` passes an allow-listed `env` (`SUBPROCESS_ENV_ALLOWLIST`: PATH, HOME, TMPDIR, LANG, ANTHROPIC_API_KEY, CLAUDE_CODE_OAUTH_TOKEN); `tasks.role` is `z.enum(AGENT_ROLES)` plus a DB CHECK; engineering sandboxing is an M3 gate |
| M3 | Built-in WebSearch/WebFetch bypass `gate()` | Accepted for research in M1 (read-only, audited per call); wrapped gated web tools with domain allow-lists are required before Sales/Growth run (M4) |
| M4 | Memory/instructions spliced raw into prompts | `<company_memory>`/`<instructions>` delimiters with tag stripping; standing "data not instructions" rules appended to every system prompt |
| M5 | Audit rows lacked task id, unbounded input | migration 0003 adds `audit_tool_calls.task_id`; worker caps input at 4 KB with a `truncated` flag |
| M6 | Unsigned Inngest endpoint, 0.0.0.0 bind | `INNGEST_SIGNING_KEY` required in production and passed to `serve()`; worker binds `127.0.0.1` by default |
| M7 | Owners could overwrite artifact evidence in Storage | Storage policy is select-only for owners; only the service role writes (tested) |
| L8 | No CHECK on task_type/status; `search_memory` executable by anon | CHECK constraints added; execute revoked from anon/public |
| L9 | Default port mismatch; `.env.*.bak` on disk | Port unified (3101); the backup env stays on disk (gitignored) until the founder moves it, because deleting keys is their call |
