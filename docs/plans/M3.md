# M3 — Build and design

Goal: from the PRD, Engineering ships a landing page into the user's own GitHub
repo and a preview deployment; going live is a K2 card; the production URL is
the evidence. Design delivers screen designs. A task that needs a tool the
user has not connected turns into a "connect" card instead of failing (ONB-3).
A failed task gets exactly one second attempt with a different approach, then
escalates (AGT-3). "Done" needs evidence a verifier confirmed (AGT-2).

Requirements: AGT-1, AGT-2, AGT-3, EXP-1, ONB-3. ADRs: 0007 (worker hosting),
0008 (connection secrets).

## Flow (worker)

`run-task` for an engineering `build_site` task:

1. `executeTask` runs the agent in `.workspaces/<taskId>` (SDK: file tools and
   Bash in that directory; mock: the fixture returns `files[]` which the worker
   writes into the workspace). Output: a `build_report` artifact, `files[]`,
   memory, and no external actions of its own.
2. `runBuildPipeline` requests the external steps **on the agent's behalf**, each
   through `gateAction` (DEC-1 is never bypassed):
   - `repo.create` (K1) → `code.ensureRepo` → `notified` with the repo URL.
   - `repo.push` (K1) → `code.pushTree(files)` → `notified` with the commit URL.
   - `deploy.preview` (K1) → `deploy.create(files)` → `notified` with the deploy
     id; `verifyEvidence({ kind: "url", ref: previewUrl })` must return 200.
   - `deploy.production` (K2, `goes_live`) → card "Go live: publish … at …?"
     with the preview link as evidence → `approve` → `deploy.promote` → verify →
     `executed`; `decline` / default → `declined` and the task still finishes
     with the verified preview evidence.
3. Evidence for `done`: the production URL when live, else the preview URL,
   both `verified: true` only after the verifier fetched them (sandbox URLs are
   served by the worker itself, so the check is real in sandbox too).
4. Missing connection (live mode, no `github`/`vercel` row): the pipeline opens
   a **connect card** (`actionKind` = the blocked action, question "Connect
   GitHub so Engineering can push the site?", options `connected` / `skip`,
   default `skip`); `connected` re-runs the pipeline, `skip` fails the task with
   a clear `last_error`. Sandbox mode needs no connections.
5. AGT-3: a failed attempt (agent error, validation error, verifier 4xx/5xx)
   re-dispatches once with `attempt: 2` and a "different approach" note in the
   instructions (`task.lastError` is quoted back to the agent). The second
   failure stays `failed`, writes a `learning` memory item and sends
   `task/escalated` (the brief surfaces it in M5).

K1 semantics change (M2 recorded K1 as `notified` without acting): K1 now
**performs** the action and records `notified`, which means "done, and the CEO
is told in the brief". The M2 unit tests are updated accordingly.

## Shared contracts (core, first)

- `tasks/types.ts`: `TASK_TYPES` += `build_site` (engineering), `screen_designs`
  (design); `ARTIFACT_KINDS` += `build_report`, `screen_designs`;
  `AgentOutputSchema.files` optional `[{ path, content }]` (≤ 60 files, ≤ 2 MB,
  relative paths only, no `..`); `TASK_OWNER` updated.
- `connections.ts`: `CONNECTION_PROVIDERS = ["github", "vercel", "gmail",
  "stripe", "meta_ads"]`, `ConnectionStatus`, `providerForAction(kind)`.
- `events.ts`: `task/escalated` `{ companyId, taskId, reason }`.
- `evidence.ts`: `EvidenceCheck` result type and `evidenceKindFor(actionKind)`.

### WP-C3 web (north-frontend)

- `/settings/connections`: one row per provider with status, account label,
  connected date; "Connect GitHub" / "Connect Vercel" start the OAuth flows
  (`/api/connections/[provider]/start` → provider authorize URL with a random
  `state` in an httpOnly cookie bound to the provider;
  `/api/connections/[provider]/callback` checks the state, then hands the
  one-time code to the worker as `connection/oauth_code`; the worker, which
  alone holds the client secret and the encryption key, exchanges it and
  stores the token — ADR 0008). When the provider's client id is absent the
  button reads "Connect (sandbox)" and records a sandbox connection, so the
  flow is testable without keys (refused in live mode). "Disconnect" revokes
  under RLS and emits `connection/revoked`; the worker drops the secret.
- Task rows show the evidence link for done tasks ("preview" / "live").
- Home gains a "Website" line: latest preview and production URLs from the
  action stream.
- Card detail: for `deploy.production` cards the evidence block links the
  preview; for connect cards it links to `/settings/connections`.
- Playwright `m3-build.spec.ts`: seed `screen_designs` + `build_site` tasks →
  preview link appears on the task row → go-live card → approve → "live" link
  → open it → the page shows the company name. Second test: decline keeps the
  preview as evidence. Third: `/settings/connections` sandbox connect/revoke.

## Decisions made while building

- **The code exchange lives in the worker, not the web callback.** The plan had
  the callback exchange the code with the service client. That would have put
  the provider client secrets and the encryption key into the web app's env.
  Instead the callback validates the state and forwards the one-time code as
  `connection/oauth_code`; `connect-provider` exchanges it and stores the token.
  The web app keeps only the public ids (`GITHUB_CLIENT_ID`,
  `VERCEL_INTEGRATION_SLUG`). The settings page shows "finishing…" until the
  worker's row lands.
- **Connect cards are cards without an action.** They are recognised by their
  option ids (`connected` / `skip`, `CONNECT_CARD_OPTIONS` in core). Settlement
  re-dispatches the task on "connected" (the pipeline resumes from the files
  still in the workspace) and fails it on "skip", the safe default. They count
  against the daily quota like any card; when the quota is spent the task fails
  with a clear reason instead of silently waiting. `finishTaskIfIdle` treats an
  unanswered card as "still waiting", so a parked task can never become done on
  the strength of its artifacts.
- **"live" vs "preview" on a task row** is decided against the company's
  current live URL (`siteUrls`), not by URL shape, so the same label logic works
  for sandbox paths and Vercel domains.
- **CI builds the worker image** (`docker build -f apps/worker/Dockerfile`),
  which runs the worker typecheck inside the image (ADR 0007).
