# M2 — Decision layer

Goal: no K2/K3 action runs without an answered card; the daily quota is never
exceeded; cards arrive by push and email; the kill switch stops everything in
5 s; every action is in the audit log. Must be complete before any agent
touches the outside world (M3, M4).

Requirements: DEC-1, DEC-2, DEC-3, kill switch, audit NFR.

## Flow (worker)

`run-task` after the agent run has persisted artifacts/memory:

1. For each requested `ActionSpec`: `gate()` with the real kill-switch flag,
   budgets and active auto rules.
2. `run` → execute through the integrations adapter (sandbox in M2) and record
   `executed` with `external_ref`; `notify` → record `notified` (brief in M5);
   `block` → record `blocked`.
3. `card` → `openCard` (DB trigger enforces quota; on quota breach the card is
   deferred: task stays `waiting_decision`, a `decision/deferred` note is logged
   and the morning cron re-tries), record action `pending` with
   `decision_card_id`, `markTaskWaiting`, send `decision/opened`, then
   `step.waitForEvent("decision/answered", { match: "data.cardId", timeout: dueAt })`.
   `null` (timeout) → `applyDefault` (K2 safe default; K3 has none → stays
   pending and is re-notified). Answer `approve` → execute via adapter → action
   `executed`; `decline` → action `declined`.
4. After all actions settle → `markTaskDone` with evidence (artifact id, or the
   adapter's external ref for action-only tasks) and ledger entry.

`decision/opened` → `notify-decision`: web push (web-push, VAPID from env;
sandbox records to `notifications`) + email (Resend adapter; sandbox records).
`company/killswitch` → `kill-switch`: `cancelOn` ends in-flight runs, the
adapter pauses active campaigns (sandbox: records), queued tasks are left queued
(dispatch refuses while the flag is on). `company/resume` → re-dispatch queued tasks.

## Shared contracts (core)

- `tasks/types.ts`: add task type `campaign_spec` (owner `growth`, artifact kind
  `campaign_spec`) whose fixture returns one `ads.start` action with `amountUsd`
  and `category: "ads"`, and `outreach_batch` (owner `sales`) returning
  `email.send.first_contact` actions. Both are K2 and exist so the decision
  layer can be exercised end to end with the mock runtime.
- `decisions/types.ts`: `CardAnswer = { cardId, optionId, answeredBy }` (exists
  as event schema); `applyDefault(card) → optionId | null`.
- `events.ts`: `decision/opened` payload `{ companyId, cardId, taskId }`,
  `decision/deferred`.

## Work packages

### WP-A2 data (north-backend) — `packages/db`

Migration `0004_m2.sql`: `decision_cards.task_id` already exists; add
`decision_cards.action_id uuid` (nullable), `push_subscriptions` (id, user_id,
endpoint unique, p256dh, auth, created_at; RLS user-scoped), `notifications`

Repositories: `decisions.ts` (`openCard(db, draft: CardDraft & { taskId })` →
`{ id, seq, day }` or throws `QuotaExceededError`; `getCard`; `listPendingCards`
(unanswered, ordered by seq); `listAnsweredCards(companyId, actionKind, limit)`;
`answerCard(db, cardId, { optionId, answeredBy })` idempotent — a second answer
throws `AlreadyAnsweredError`; `cardsOpenedToday(companyId)`),
`autoRules.ts` (`createAutoRule`, `listActiveAutoRules` → core `AutoRule[]`,
`deactivateAutoRule`), `pushSubscriptions.ts` (`upsertPushSubscription`,
`listPushSubscriptions(userId)`, `removePushSubscription`), `notifications.ts`
(`recordNotification`, `listNotifications(companyId)`), `users.ts`
(`getProfile(userId)` with timezone and quota, `updateQuota`), and
`actions.ts` gains `setActionStatus(db, actionId, status, externalRef?)` —
note `actions` is append-only, so status changes are new rows: implement
`recordActionTransition` that inserts a follow-up row referencing the original
via `payload.supersedes` and keep `listRecentActions` returning the latest row
per logical action. Integration tests for quota through `openCard` (4th card
throws), idempotent answers, RLS on cards/subscriptions/notifications.

### WP-D2 worker (orchestrator)

`run-task` action loop with `step.waitForEvent`, default application, adapter

Decisions made while implementing (ask if any should change):

- Push subscriptions and the VAPID key are optional; `/settings` hides the
  button when `NEXT_PUBLIC_VAPID_PUBLIC_KEY` is absent, and push/email in
  sandbox mode are recorded in `notifications` instead of sent.
- The decision email deep-links to `/c/<slug>/decisions/<cardId>`; the worker
  resolves the slug with `getCompanyById`.
- Card evidence shows the task and the latest artifacts of the requesting role;
  a direct action→artifact link is M3 work.
