# M4 — Growth, sales and the outcome ledger

Goal: a test campaign runs end to end; spend, clicks and signups appear in the
ledger; caps are never exceeded; first sales emails go out only after a card.

Requirements: OUT-1, OUT-2, budget protections, Growth K2, Sales K2.

## Deliverables

- Adapters (live + sandbox): Meta Marketing API, Google Ads, Gmail send, lead
  list upload, PostHog/Vercel Analytics read, Stripe read (user's account).
- Growth role: campaign spec → K2 card with budget → start → hourly metric
  collection → pause when daily cap reached (BudgetGuard).
- Sales role: lead research (web) + personalised first-contact email → K2 card
  per batch → send → reply tracking as metric.
- Ledger UI: `/c/[slug]/ledger` with attribution rows, channel report, export CSV.
- Metric collectors (`collect-metrics` cron) with provenance.

## Acceptance test

Smoke with sandbox adapters: campaign with $10/day cap → simulated spend events
→ ledger shows spend, clicks, signups; the 11th dollar opens a cap card and the
campaign pauses. Sales: 5 leads → one card → 5 sandbox sends with message IDs →
replies simulated → metric updated. Live run on test ad accounts recorded under
`docs/evidence/M4/`.
