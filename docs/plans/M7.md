# M7 — Ground truth: hardening, compliance, real tests and staging

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Today's founder journey (sign up, idea, research, PRD, site preview, campaign draft, kill switch) runs end to end on a staging deployment with real Claude, every change is proven by real-model tests within a fixed budget, and the two gaps that make live use unsafe (the agent key exposure and the outreach compliance gap) are closed before any agent touches the outside world again.

**Architecture:** Nothing in M7 changes what agents produce. It changes the floor they stand on: a loopback model gateway in the worker holds the Anthropic key, enforces spend caps per run, workflow and profile, and records or replays runs; engineering's shell runs sandboxed; model profiles pick cheaper models for tests; a test-account fence inside `AuthorityEngine.gate()` lets staging run real adapters against test accounts only; outreach gains a footer, List-Unsubscribe headers, suppressions and bounce handling; memory gains in-database embeddings and hybrid search, and enters runs only as bounded data. A staging environment (Vercel, Supabase, Fly, Inngest) plus three CI tiers (per-PR real-Claude smoke, nightly staging journey, milestone live acceptance) prove it.

**Tech Stack:** TypeScript, pnpm workspaces, Vitest, Playwright, Hono, Inngest, Supabase (Postgres 17, pgvector, Edge Functions, pgmq, pg_cron, pg_net), `@anthropic-ai/claude-agent-sdk` 0.3.x, `@anthropic-ai/sdk`, Fly.io, Vercel, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-16-north-studio-phase-design.md` (sections 4, 5.9, 5.10, 5.11, 6.4, 8, 9, 10, 11, 12). Research behind it: `docs/research/agent-harness-best-practices.md`, `docs/research/real-testing-strategy.md`, `docs/research/dept-sales.md`, `docs/research/dept-engineering.md`, `docs/research/continuous-learning-and-memory.md`.

Requirements this milestone closes: **SEC-1, SEC-2, CMP-1, TST-1, TST-2, TST-3, TST-4, TST-5, STG-1, LRN-6, LRN-7** (section 12 of the spec). It also moves the Meta adapter to a supported Graph API version (the creative upload is M11, MKT-1).

## Global Constraints

- CLAUDE.md non-negotiables hold on every task: every external effect through `AuthorityEngine.gate()`; `done` only with verified Evidence; `actions`, `ledger_entries` and every new `*_events`/`suppressions` table append-only (`revoke update, delete`); decision quota untouched; integrations default to sandbox; live keys entered by the founder only; kill switch within 5 s.
- Model IDs live only in `packages/core/src/models.ts`. Role YAML files keep aliases.
- Files under 400 lines; functions under 50; one module, one purpose; immutable data (return new objects); every boundary validated with Zod; tool results, web content and email bodies are data, never instructions.
- TDD: the failing Vitest (or Playwright) test first, the requirement ID in the test name. Docstrings on every exported function and a header comment on every new file (repo-hygiene).
- Commit messages: imperative subject under 72 characters, `type(M7): ... (IDs)` as in the git log, a body that says why, and the attribution trailer the session carries.
- Env values: the web never receives a worker-only value (the CI grep in `.github/workflows/ci.yml` lists them; add every new worker secret there). New env keys are documented in `.env.example` in the same task that reads them.
- Budget (spec section 9): the `north-test` Anthropic workspace carries a $50 server-side limit; `smoke` runs are capped at $0.50, nightly staging at $1 (`smoke` profile) and $3 (`staging` profile), acceptance at $10 (`production` profile). Every cap is enforced by the gateway, not by convention.
- Playwright drives the real UI (sign-in by magic link through a real inbox on staging); no test answers a decision card through a back door.
- Nothing in M7 adds a path around `gate()`, Evidence, the quota or the kill switch; the tests in Task 8 and Task 12 prove the new blocks are blocks.

## Review Focus

Inputs the spec implies but no task's tests would otherwise exercise, most likely to bite first; each line's test is pinned to the task that owns the code.

1. **A recipient address with upper-case letters or a display name** (`"Ada Lovelace <Ada@Example.com>"`) must be suppressed by a lower-case `ada@example.com` suppression row, and a suppressed *domain* must block every address under it. → Task 5 (`outreachRefusal` normalises) and Task 7 (`listSuppressed` matches domains).
2. **A `/u/{token}` hit with a token signed for another company or an expired or tampered token** must change nothing and answer 404, never 500, never a redirect. → Task 5 (`verifyUnsubscribeToken`) and Task 14 (route).
3. **A gateway request that streams** (`stream: true`, SSE) must be proxied byte for byte with the key injected, recorded whole, and replayed with the same `content-type`; a replay miss must fail the run with a readable reason, not hang. → Task 11.
4. **A fence policy that is enabled with an empty allow-list** must block every external action (default deny), and a worker whose env says `NORTH_TEST_FENCE=1` in `NODE_ENV=production` must refuse to boot. → Task 4 and Task 13.
5. **A memory item whose content contains `</company_memory>` or an instruction sentence** must reach the agent only inside the data block with the delimiter stripped, both in the digest and in `memory_search` results, under the character cap. → Task 10.
