# M7 founder checklist

What only the founder can create, enter or verify before the M7 staging
acceptance can run (spec `docs/superpowers/specs/2026-10-16-north-studio-phase-design.md`
section 10, row M7, plus every founder-gated item recorded during M7). Every
name below comes from `docs/evidence/README.md`, `docs/runbooks/staging.md`,
`.env.example` or the workflows; the runbook section is given for each step.

Rules:

- Values never go into a file, a commit, a ticket or this checklist: write
  `<your key>`. Staging never shares a value with production.
- "Fly" is a secret of the app `north-worker-staging`
  (`fly secrets set NAME=<value> --config apps/worker/fly.staging.toml`).
  "Vercel `staging`" is an environment variable of the Pro team's `staging`
  custom environment (`vercel env add <NAME> staging`). "GitHub `staging` /
  `acceptance`" is a secret or variable of both GitHub environments:
  **environment secrets are not shared**, so `acceptance` gets its own copy of
  every entry (the same values).
- Placeholders: `<web>` the production web host (staging is `staging.<web>`),
  `<domain>` the mail domain, `<staging ref>` the `north-staging` project ref,
  `<test-org>` the GitHub test organisation.
- Status is `open` until the founder has done the step; a verification row is
  done only when its evidence file exists.
